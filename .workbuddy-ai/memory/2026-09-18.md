## Tooling trap — duplicate proxy variables break the compile

`compile-th3.ps1:691` calls `Start-Process`, which builds the child environment
from a case-INSENSITIVE dictionary. This machine's process env carries BOTH cases
of the same name — `HTTP_PROXY`/`http_proxy` and `HTTPS_PROXY`/`https_proxy`
(each `http://127.0.0.1:6590`) — so the compile dies with:

    Start-Process : Item has already been added.
    Key in dictionary: 'http_proxy'  Key being added: 'HTTP_PROXY'

`Set-Item env:... -Value $null` is NOT enough: the PowerShell `env:` provider is
case-insensitive and does not remove both native entries. The call that works,
in the SAME PowerShell invocation as the compile (shell state does not persist
between tool calls):

    foreach($n in 'HTTP_PROXY','HTTPS_PROXY','http_proxy','https_proxy',
                  'ALL_PROXY','all_proxy','NO_PROXY','no_proxy'){
      [System.Environment]::SetEnvironmentVariable($n, $null, 'Process')
    }
    $env:APPDATA = [Environment]::GetFolderPath('ApplicationData')
    & .\compile-th3.ps1 -Project all *> "$env:TEMP\_all.txt"

Also this session: the PowerShell tool returned NO stdout at all (every call
reported only "exit code 0"). Redirect to a file (`*>` writes UTF-16, read with
`iconv -f UTF-16LE`) and read that file with the Read/Bash tool instead.

`-Project all` compiles only the MAIN entry (workspace + installed). Compiling
every `.mq4` needs `-SourceFile <full path>` per file, per AGENTS.md.

## The audit's model must mirror the code — a lesson from P-BK-85

`tools/base-count-audit.py` keeps a Python model of the walk (`walk_span`) beside
the static gates. When a change lands in `BaseKnotBarCount`, the MODEL has to
move with it. P-BK-85 changed the exit from `end = head - 1` (assumed) to a
verified CLOSE, and the model kept the old line — so the model would have
certified a reading the code no longer produces. That is the failure mode to
watch: a stale model is worse than no model, because it passes.

What the model needed: a second series. `flags[i]` is the body being inside the
band; `closed[i]` is the CLOSE being outside it. Both are needed because the
body test and the close test disagree on exactly one candle — the one that poked
out and closed back inside — and that candle is the whole point of P-BK-85.
`walk_span(flags, right, closed=None)` defaults `closed` to `not flags`, which is
the retired assumption, so old scenes keep their old numbers.

The scene pair that pins it: `reclose` (shift 39 did NOT close outside → 18) and
`exitok` (the same tape, shift 39 DID → 19). One bit moved, two different
numbers, so neither can be reached by accident.

## P-BK-86 — the box-side note wears its own plate

User: «این اطلاعات میره داخل کندل ها خونده نمیشه اینو باید چیکارش کنیم که
هیچ تداخل نداشته باشه و همیشه بتونه خونده بشه».

**Cause.** The box-side note was a CHART-SPACE `OBJ_TEXT`. Two consequences,
one cause:

1. MT4 paints chart art in that same layer, so candles and level lines came out
   over the glyphs. Measured on his crop: in `_note1.png` the red level line
   (rows 189-191) is drawn across the note's rows (184-220), cutting "16 bars".
2. `OBJ_TEXT` cannot carry a background, so there was nothing to read the ink
   against. `Z_CHART_LABEL` (100) did not help: the custom price line rides the
   same rung, and at equal ZORDER the later-created object wins.

**Fix — one move, both answers.** The box-side home is now a SCREEN PAIR:
`OBJ_LABEL` for the ink (the panel layer is above every chart-space rung) plus
`OBJ_RECTANGLE_LABEL` as a plate behind it, filled with
`CHART_COLOR_BACKGROUND`. Invisible over empty chart, a cut-out where the
candles are. The corner row (rung 2) is untouched.

**New owners in `Biotak/BaseKnotTool.mqh`:**

| owner | job |
| --- | --- |
| `BK_NOTE_PLATE` `"_BG"` | the plate's name = the note's name + this |
| `BaseKnotInfoPlateName(infoName)` | the ONE spelling of that suffix |
| `BaseKnotInfoWipe(pfx)` | deletes the PAIR — used by all three delete sites |
| `BaseKnotNotePlateH()` | `PnlRawLineH(BKInfoFontPt()) + 2*PAD_Y` |
| `BaseKnotNotePlateTop(...)` | the two top-left corners from the projected corner |
| `BaseKnotNotePlatePx(...)` | the plate's box, width from `PnlRawTextW` |
| `BaseKnotNotePlateDraw(...)` | the plate itself, rung `Z_BOX_INFO` (60) |
| `BaseKnotNotePlateFollow(pfx,t2,top)` | re-projects, read-guarded |

**The follower is the price of going screen-space.** A chart-space object
follows the chart by itself; a screen one does not. It is called from the
child-move path (a drag) and from `BaseKnotPlaceBadges` (which the 500 ms pump
and `CHART_CHANGE` both reach), so scroll, zoom, resize and a new bar are all
covered. It writes only when the pixels moved — four terminal reads otherwise.

**Upgrade path.** `ObjectCreate` never re-types an object it finds, so a
pre-plate build's `OBJ_TEXT` note is purged by one `OBJPROP_TYPE` read.

**Two properties worth keeping:**

- the plate's fill and the note's ink both come off `CHART_COLOR_BACKGROUND`
  (the ink through `BaseKnotFgForBg()`), so they cannot disagree about which
  way round they are;
- the geometry has ONE owner (`BaseKnotNotePlateTop`), so the writer and the
  follower cannot place the plate and the ink by two spellings of one sum.

**Gates.** `tools/base-count-audit.py` grew `check_note_plate` (13 rows) and
8 mutants; two older gates were re-taught: the rung gate in `check_note_life`
(the plate's rung now lives in its own drawer) and the "only the last lines
differ" gate in `check_note_home` (both homes are screen objects now, so
`OBJPROP_PRICE`/`OBJPROP_TIME` must NOT appear in the writer).

**Result.** 11/11 `.mq4` compile `0 errors, 0 warnings`; all 11 audits green
(base-count `151/151`).

## P-BK-86b — the plate was measured against a guess (the advance table)

`PnlRawTextW(text, BKInfoFontPt())`, and `PnlAdvUnits` (the ONE owner of "the
width Arial Bold draws this character at") had no entry for `[`, `]` or `|` —
all three of the note's own punctuation. They fell through to its
"unknown -> a mid-weight capital" value of 611, so the plate came out
**+1273 units = +1.27 em too wide** (+14 px at 8pt/96dpi, +20 px at 8pt/144dpi):
an empty tail on the one surface whose whole point is that its box fits its ink.

the table (`Biotak/UtilityFunctions.mqh`). After the fix the plate is
**+55 units (+1 px at 8pt/96dpi) wider** than the ink — the safe direction.

**The rest of the table is sound.** Only 2 of its 88 entries differ from the
font: `'` (278 vs 238) and `Y` (722 vs 667). Left alone — both lean wide, and
`Y` is in the note's own `BUY`.

**Nothing else measured those three.** The panels split their option lists on

## P-BK-87 — the note is kept inside the window

**The hole P-BK-86 opened.** Going screen-space traded one collision for another. A
chart-space object is clipped by the chart; a SCREEN object is not — it is projected
to whatever pixel the box' corner lands on, and off-window pixels do not paint. So a
box scrolled to the top edge (or to the right one) took the note with it. The user's
own words for the whole line of work are «همیشه بتونه خونده بشه» — a note that
vanishes at the window edge is not readable.

**Where it is fixed.** ONE place, and it is already the owner of the pair's position:
`BaseKnotNotePlateTop` now takes `pw` and fits the pair into the window — top and left
`BK_NOTE_EDGE_MARGIN` (4), right `cw - MathMax(8, inpLabelsMarginLeft)` (the label
family's own boundary, the one its countdown tag already uses; past it sits the price
scale), bottom `ch - BK_NOTE_BOTTOM_SAFE` (20, for the date-scale bar).

**Why the bottom reserve is spelled here rather than reused.** `PNL_BOTTOM_SAFE` (30)
lives in `BiotakPanels.mqh` — the UI half, which the Lite entry does not compile. A
domain-half module that read it would break Lite (P-BUILD-01). Lite compiles green, so
the copy is the honest choice.

**A second hole, found while fixing the first.** The follower only ever MOVED the
plate; it never resized it. The note's own text is not constant (the bar count, the
risk, the type), so a plate that only moves is sooner or later too narrow for the ink
it carries — the one thing a plate exists to prevent. `BaseKnotNotePlateW` is now the
width's ONE owner, and the follower measures with it and writes XSIZE/YSIZE. Steady
state went from four terminal reads to six; still reads only.

**The gate was re-taught, not loosened.** `check_note_home` asserted this module reads
NO `inpLabelsMargin*` at all — its point was that the corner slot is PUSHED IN from
above, never guessed here. The fit is not the column, so the row now strips the fit's
own body before searching: the module still never places the corner row with a margin.

**Gates.** `check_note_plate` grew 5 rows (the fit, its right boundary, its bottom
reserve, the width's one owner, the follower's size step) and 5 mutants. One of those
mutants earned its keep immediately: the first version of the size row only looked for
the property NAME, and the follower's read-guard also mentions XSIZE — so the mutant
walked straight through it. The row now requires the actual writes.

**Result.** 11/11 `.mq4` compile `0 errors, 0 warnings` (Lite included — that IS the
P-BUILD-01 gate); base-count selftest `159/159`, plain run clean; panel-wiring 139/139,
write-budget 56, gesture-budget 18/18, zorder 10/10, ui-text 11/11, chart-label 31/31,
